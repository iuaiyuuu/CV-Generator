# info/PROJECT/

One `.md` entry per project, created from [`project.template.md`](project.template.md). Include personal, academic, freelance, competition, open-source, and work projects.

## Tell each project in this order

| Part | Answer this | Example (fictional) |
|---|---|---|
| **Title** | What is it called? | Sales Dashboard |
| **1. Problem** | Who had which problem, and why did it matter? | The campus cooperative kept sales in spreadsheets, and the managers guessed which products sold well. |
| **2. Solution** | What did the project do about it? What can it do now? | A dashboard that shows revenue by category and by month, built from cleaned sales data. |
| **3. My part** | What did *you* personally do? Solo or team? | Solo: cleaned the data, wrote the queries, built and deployed the dashboard. |
| **4. Tech stack** | Only what you really used. | Python (pandas), Streamlit, SQLite, Git |
| **5. Results** | Real numbers, with an "as of" date if they keep growing. | 12,000 rows cleaned; 3 product categories made up most of the revenue. |

Then skills demonstrated, which jobs it fits, and (optional) what **not** to claim.

## Tips

- Write raw and detailed. The AI selects and rephrases per job, so more true detail means better tailoring.
- Separate **Solution** (what the system does) from **My part** (what you did). A CV needs both, and employers read them differently.
- Put private or unverified parts in section 8, for example a technology you do not want named. The AI obeys it in every CV.
- No number is better than an invented number.
