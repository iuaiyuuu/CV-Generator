## 1. Problem

The campus cooperative kept its sales in spreadsheets and paper receipts. The managers could not see which products mattered, so they guessed what to restock.

## 2. Solution (what was built)

A dashboard the managers can open in a browser, built from the cooperative's cleaned sales data:

- revenue by product category
- revenue by month
- a clean data set stored in SQLite, so the numbers can be rechecked

## 3. My part (what I personally did)

- Solo project: cleaned 12,000 transaction rows (duplicates, missing prices, inconsistent product names)
- Stored the cleaned data in SQLite and wrote the queries in plain SQL
- Built and deployed the dashboard
- Committed to Git about weekly
- Presented the findings to the cooperative managers

## 4. Tech stack (only what you actually used)

- Python (pandas), Streamlit, SQLite, Git
- Deployed on Streamlit Community Cloud
- No Docker, no cloud data warehouse

## 5. Results (only real numbers)

- 12,000 rows cleaned
- 3 product categories made up most of the revenue
- Dashboard used by the managers in their monthly meeting (reported by the user)

## 6. Skills demonstrated

- Python (pandas), data cleaning, Streamlit dashboards, basic SQL, Git, presenting findings

## 7. Good for applying to

- Junior data analyst, business analyst

## 8. Not to claim or mention

- Not production software for a company; it is a student project for the cooperative
